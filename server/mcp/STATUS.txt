- Single tool: gmail_send

- Native messaging host name
- Gmail API scopes
- Logging settings

4. Native Messaging Manifest (gmail_mcp_host.json)
- Windows registry entry or Linux config
- Points to mcp_gmail.js executable path
- Defines allowed Chrome extension IDs

POTENTIAL PROBLEMS

1. Token Management

Problem: OAuth tokens expire (1 hour)
Solution: Use chrome.identity.getAuthToken({interactive: false}) with auto-refresh

2. Native Messaging Setup

Problem: Complex OS-specific configuration
Solution: Provide setup script that writes registry/config files

3. Extension Not Installed/Running

Problem: MCP server can't connect if extension disabled
Solution: Graceful error handling, check extension status, clear error messages

4. Multiple Gmail Accounts

Problem: User logged into multiple Gmail accounts
Solution: chrome.identity uses default account; allow account_hint parameter

5. MIME Message Construction

Problem: Complex email formatting (attachments, HTML, etc.)
Solution: Start with plain text only for MVP; use library like emailjs-mime-builder later

6. Rate Limiting

Problem: Gmail API has quota limits
Solution: Implement exponential backoff, surface quota errors to user

7. Chrome Store Policy

Problem: OAuth permissions require Chrome Web Store review
Solution: For personal use, load unpacked extension; for distribution, submit for review

ERROR HANDLING

Server Layer (mcp_gmail.js)

- Connection timeouts (native messaging)
- Malformed responses from extension
- Extension not available
- JSON-RPC protocol errors

Extension Layer (background.js)

- OAuth failures (user denies permission)
- Token refresh failures
- Gmail API errors (invalid recipient, quota exceeded)
- Network failures

Response Format

{
  "success": true/false,
  "messageId": "abc123...",
  "error": "Descriptive error message"
}

---
RETRY HANDLING

Strategy

1. OAuth Token: Auto-retry once with {interactive: true} if expired
2. Network Errors: 3 retries with exponential backoff (1s, 2s, 4s)
3. Rate Limits: Respect Retry-After header, max 5 retries
4. User Errors: No retry (invalid email format, etc.)

Circuit Breaker

- After 5 consecutive failures, pause for 60 seconds
- Log detailed diagnostics
- Return clear error to user

MCP ATTACHMENT SIZE LIMITATIONS - CRITICAL ISSUE
===================================================================

PROBLEM SUMMARY:
Sending file attachments via gmail_send MCP plugin does not work due to the MCP protocol's 1MB content limit. While the Gmail API supports 25MB attachments, the MCP protocol requires the entire JSON-RPC message (including base64-encoded file content) to remain under 1MB. Base64 encoding increases file size by 33%, meaning files larger than 500-700KB will exceed the limit. In practice, even 80KB files trigger errors due to JSON overhead. The filesystem MCP plugin reads files but also fails on size constraints. It does NOT access Google Drive files as advertised. There is no workaround - attachments via MCP are not viable for anything beyond trivial file sizes.
